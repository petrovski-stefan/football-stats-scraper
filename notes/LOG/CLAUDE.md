# notes/LOG/ — the dated record of changes

**Written in ASD-STE100 Simplified Technical English.** Short sentences, one idea each.

The rule of this group: add dated entries only. Never change an old entry. The rules for every note are in `notes/CLAUDE.md`.

## Read

`MIGRATIONS.md` records each rename, move and deletion: of a module, a path, a column, a field, a note or a league. It also records each item of an IDEAS or PLAN note that is done.

- **Read it when code or a note cites something that does not exist:** a module, a path, a column or a note. Search for the old name. Its entry tells what changed.
- **Read it to see what was done** from the IDEAS and PLAN notes.
- **Old entries keep the paths and names of their date.** That is correct. Do not change them.

## Write

- **Add an entry for:**
  - a rename, a move or a deletion;
  - an item of an IDEAS or PLAN note that is done;
  - a dropped field, with the date, who decided and why;
  - the out-of-date facts that were fixed in one session (`notes/CLAUDE.md` §3, rule 2).
- **Put the entry under the heading of the day when the change was done:** `## YYYY-MM-DD`. Add the heading if it is not there. The newest day is at the end.
- **Give one bullet for each change.** Start it with a short summary in bold. Name the files, paths and columns that changed. Write "(the user)" when the user decided.
- **A removed league:** give a count only. Never write its name.
- **A correction of an old entry** is a new entry that cites the old one.
- **The text above the first date can change.** The dated entries cannot.
