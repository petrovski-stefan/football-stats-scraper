## Notes per idea

### 1 — Markets (with 3 and 5 since 2026-10-13)

In this order: choose the markets, write one explainer per market, then group the notes and the code by market.

**Picking (was 1):**

What the scraped data can support:

- **Has odds, so it can be tested against a price:** match result (1X2), Asian handicap, the main over/under line.
- **Settled from scores, but no odds scraped:** both teams to score, HT/FT, half-time result, correct score, clean sheet / win to nil, other goal lines (6.5 already exists).
- **Needs the live-page scrape (slow):** goal-timing markets (late goal, first-goal time) and cards.
- **Not in the data:** corners (only inside history rows), shots, player markets.

A market without scraped odds can have a model. But nobody can check that model against the bookmaker.

**Explainers (was 5):**

- One doc per market. It sorts every fact into three kinds:
  - **definitional** — true by the settlement rule (no comeback with fewer than 3 goals), so it is never calculated;
  - **structural** — follows from the goal model, so it is derived once, in the doc;
  - **empirical** — needs data. Only these facts are measured and preregistered.
- Written like GLOSSARY: concepts and mathematics, invented example numbers, no project results.
- **Ask the user before you write each explainer:** depth, which bets, how far into the price (implied probability, margin, EV, staking), mechanisms, formula detail, language, and if it must be complete in itself (the questions asked before the comebacks explainer).
- **Format added after two outside reviews that the user ran (2026-10-04):**
  - Every structural card has a Basis line: proof (true for every setting of the model), grid check (true for the stated settings only) or example.
  - Calculations about tests (sample sizes, counts by chance) have the label statistical design, not structural.
  - A second, independent calculation checks every number before it goes in.
  - The summary table gives each claim its own row, with exactly one basis (proof, grid check, example, or assumption for the model itself).
  - A grid-check row starts with "In the checked settings". An example row names the example.

### 9 — ML / deep learning

- ML combines weak signals better. But it cannot create a signal that the inputs do not have.
- At ~100k tabular matches, gradient boosting (for example LightGBM) is the realistic tool. At this size, deep learning is rarely better. Sequence models are worth a look only for in-play timelines.
- The evaluation rules (fresh data for any tested claim) stay the same.
