## Notes per idea

### 1 — Markets (with 3 and 5 since 2026-10-13)

In this order: pick the markets, write an explainer per market, then group the notes and the
code by market.

**Picking (was 1):**

What the scraped data can support:

- **Has odds, so it can be tested against a price:** match result (1X2), Asian handicap, the
  main over/under line.
- **Settled from scores, but no odds scraped:** both teams to score, HT/FT, half-time result,
  correct score, clean sheet / win to nil, other goal lines (6.5 already exists).
- **Needs the live-page scrape (slow):** goal-timing markets (late goal, first-goal time) and
  cards.
- **Not in the data:** corners (only inside history rows), shots, player markets.

A market without scraped odds can be modelled, but never checked against the bookmaker.

**Explainers (was 5):**

- One doc per market, sorting every fact into three kinds:
  - **definitional** — true by the settlement rule (no comeback with fewer than 3 goals), so
    never computed;
  - **structural** — follows from the goal model, so derived once, in the doc;
  - **empirical** — needs data; only these get measured and preregistered.
- Written like GLOSSARY: concepts and math, invented example numbers, no project results.
- **Ask the user before writing each explainer:** depth, which bets, how far into the price
  (implied probability, margin, EV, staking), mechanisms, formula detail, language and
  self-containment (the questions asked before the comebacks one).
- **Format added after two outside reviews the user ran (2026-10-04):** every structural card
  has a Basis line: proof (true for every setting of the model), grid check (true for the
  stated settings only) or example. Calculations about tests (sample sizes, counts by
  chance) are labelled statistical design, not structural. Every number is checked by a
  second, independent calculation before it goes in. The summary table gives each claim its
  own row with exactly one basis (proof, grid check, example, or assumption for the model
  itself); a grid-check row starts "In the checked settings", and an example row names the
  example.

**Grouping by market (was 3):**

- 40 tracked files outside `notes/` mention `notes/` (2026-10-13; 21 on 2026-10-01): code,
  the CLAUDE.md files, skills, agents and the holdout hook. `modelling/experiment.py` and
  `modelling/filter_study.py` write into `notes/`.
- Notes that span several markets (PREREGISTRATION, STATS_PRIMER, GLOSSARY) go

### 9 — ML / deep learning

- ML combines weak signals better, but it cannot create signal the inputs lack.
- At ~100k tabular matches, gradient boosting (e.g. LightGBM) is the realistic tool. Deep
  learning rarely beats it at this size; sequence models are worth a look only for in-play
  timelines.
- The evaluation rules (fresh data for any tested claim) stay the same.
