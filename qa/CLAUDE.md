# qa/ — corpus validation

## 1. The validate command

`uv run python -m qa.validate` checks internal self-consistency and **exits non-zero on any failure**. Its one cross-source check is the page's final table against our rebuilt standings (§5); the football-data.co.uk check was retired (see `notes/MIGRATIONS.md`).

## 2. Don't soften the canary

Do not soften the canary in `qa/` to make the run green. A failure is a finding about the data, not a bug in the check.

## 3. The current exit-1: friendly tournaments in the event store

It is a real finding rather than a stale one. **2 of 1,395 matches (0.14%) show 9-10 substitutions by one side**, which is impossible in competitive football. Both are pre-season friendly tournaments — `Germany Liga Total Cup` and `Emirates Cup` — that `domain/scope.py:FRIENDLY_MARKER` misses because neither name contains "friendly".

The threshold is calibrated to permit a legitimate 6th substitution (the concussion protocol; match 2789190 is a real EPL example), so only genuine contamination trips it.

**Fixing it means deciding how such matches are excluded, which is a corpus-definition call, not a code change.** Don't patch the threshold or the marker without that decision from the user.

## 4. Goals have an oracle; events do not

**Goals: the half-time score is a free oracle.** `qa/goals.py` reconciles all goals against the stored full-time score _and_ goals with `minute <= 45` against the stored half-time score. The second check is what tests the minute rather than the count: mishandle stoppage and a 45+3' goal lands in the second half, and the check fails loudly on every such match. `minute` and `stoppage` are stored separately for exactly this reason (45 and 3, never 48). History matches from other competitions have no stored score, so only the internal checks apply to them; that asymmetry is reported, not hidden.

**Events: `qa/events.py` has no free oracle.** Nothing in the corpus independently counts cards. So it checks structure (ranges, kinds, contiguous index, ordering, at most six substitutions per side) plus wide per-match rate bands, and says so rather than implying the same guarantee `qa/goals.py` gets from the half-time score.

## 5a. The staged schedule file (`qa/schedule.py`, 2026-10-07)

Each `data/finished/1_raw/` schedule gets its own report: the universal checks (rows, the declared columns, a unique `match_id`, no dead column except `s1_stage`), then HT goals ≤ FT goals, the odds (`qa/odds.py`), kickoffs inside the season's years, no team twice within 24 h, and the season's shape. Every kept "League" stage is a k-fold round robin, so each round must hold floor(teams ÷ 2) matches, no team may play twice in one round, and every pair of teams must meet equally often. A missed or doubled match fails the size and pair checks, and so does a real event like a team withdrawn mid-season. The once-per-round check (2026-10-08) catches a page whose rounds are only labels: on such a page about one match in twelve is filed under a neighbouring round, so a team plays twice inside one page round although every round's size is right. There the standings are still right (they are rebuilt by kickoff time); anything that reads `s1_round` as a real round is not. **`qa/odds.py` holds the odds checks once, for any table given its column names**: the old base files (`qa/league.py:BASE_ODDS`) and the staged ones (`qa/schedule.py:STAGED_ODDS`) both call it. First finding, 2026-10-07: one row has an opening goal line of 0.25 on the page, implausible before kickoff (its league was removed from the project on 2026-10-10, at the user's request, after the user checked the page by hand). Second, 2026-10-08: 97 rows in 8 league-seasons whose O/U and AH cells repeat their 1X2 prices, and one whose 1X2 repeats its AH. That was a scraper bug, fixed the same day (`scrapers/schedule.py:drop_stale_odds`); the overround checks flag every such row until those seasons are re-scraped. Third, also 2026-10-08: the 2026-10-07 row belongs to a page error of 6 and 19 Oct 2024, where the opening O/U line equals the AH line's size. A re-scrape does not change page values. The range check sees it only when the line is below 1.5, so `odds.check_goal_line_above_handicap` (the user, 2026-10-08) fails any row whose O/U line is not above the AH line's size. In the corpus of 2026-10-08 that is the 2026-10-07 row alone, out of 29,072 rows with both lines. **Since 2026-10-10 the largest line a row may carry depends on its 1X2 favourite's price** (`odds.LINE_LIMITS`, the user's call): the fixed limits (a 4-goal handicap, a 5.5 total) failed real mismatches, where a 1.01–1.04 favourite carries a 4.25–6 handicap and a total up to 7, and they let a 3.5 handicap on a 1.60 favourite pass.

## 5. The page's final table checks our rebuilt standings

The standings the analysis uses are rebuilt from stored results at each kickoff (`features/schedule_multi.py`; the user's decision, 2026-10-06), so `qa/final_table.py` is the only thing that holds them against the site. For every staged schedule (`data/finished/1_raw/`) it rebuilds each stage's table from all its stored results and compares every team's P, W, D, L, GD and PTS with the page's final table, read once per stage by the scraper. Rank only has to fall inside the block of positions the teams level on points share: the page breaks a tie on points by its league's rule (head-to-head in Spain, Portugal, Italy and Poland, most wins in Belgium), ours by goal difference and goals for. The user accepted that difference on 2026-10-07, since every count stays exact.

A deduction confirmed in public reports is declared in `domain/deductions.py` (details in `notes/POINTS_DEDUCTIONS.md`) and added to the rebuilt points before comparing (where the page's table applies less than the official total, `deductions.PAGE_TOTALS` holds the page's figure and the check uses it: one team, Adana 2025-26, the user's exception of 2026-10-10); stage 3 itself keeps the points earned on the pitch (option A, the user, 2026-10-07). Any other failure is a data finding (§2): an undeclared points deduction, a missed match, a wrong score, or a league whose points carry into a later stage before its carry-over rule exists. A missing final table fails too, because the rebuild is then unchecked. EPL 2025-26 passed on 2026-10-07, 20/20 teams. The first full run, the 54 DEV seasons on 2026-10-07, passed 31: the failures were points deductions, the page ordering teams level on points by head-to-head or most wins (accepted since, see above), two matches the page's table leaves out (one abandoned and awarded), and one odds row. The list and the decisions still open are in `notes/PLAN_2026-10-05_staged_pipeline.md`, step P6.
